# PLT-52 — .NET 10 LTS e allineamento dipendenze

**Data:** 30 settembre 2026  
**Esito:** completato

## Cambiamenti

- Tutti i cinque progetti backend ora targettano `net10.0`. Il repository fissa SDK `10.0.400` in `global.json` con roll-forward `latestFeature`; `dotnet-ef` è uno strumento locale fissato a `10.0.12`.
- `backend/Directory.Packages.props` centralizza le versioni. I cinque `packages.lock.json` sono stati generati e il restore in Docker e in CI futura deve usare `--locked-mode`.
- EF Core, Identity e tooling EF sono `10.0.12`; Oracle `MySql.EntityFrameworkCore` è `10.0.9`, basato su Connector/NET `26.7.0`. Il test stack, Serilog e Swashbuckle sono aggiornati e coerenti con .NET 10. NUnit resta all’ultima major 4 per preservare la semantica sincrona di `Assert.ThrowsAsync` adottata dai test.
- Le immagini del Dockerfile usano SDK e ASP.NET runtime `10.0`; il publish riusa il restore locked. L’aggiornamento a Microsoft.OpenApi 2.x ha richiesto l’adeguamento dei filtri schema/security e dello snapshot writer.
- Gli snapshot OpenAPI sono stati rigenerati. Restano presenti tutte le route e le proprietà del contratto precedente; sono riflessi i campi required derivati dai DTO, i limiti degli attributi e il formato aggiornato OpenAPI 3.0.4.

## Matrice supportata

- [.NET support policy](https://dotnet.microsoft.com/en-us/platform/support/policy): .NET 10 LTS supportato fino al 15 novembre 2028 secondo la policy consultata durante l’upgrade.
- [EF Core support policy](https://learn.microsoft.com/en-us/ef/core/what-is-new/): EF Core 10 segue la linea LTS .NET 10.
- [Oracle Connector/NET EF Core guide](https://dev.mysql.com/doc/connector-net/en/connector-net-entityframework-core.html): il provider supporta EF Core 10 e MySQL 8.0+; MySQL 8.4 LTS rientra nella matrice.
- La soluzione è stata ripristinata e testata contro MySQL 8.4 tramite Testcontainers. Il database applicativo locale non è stato consultato né modificato.

## Verifiche eseguite

- `dotnet --version` dalla root: `10.0.400`.
- `dotnet tool restore` e `dotnet tool run dotnet-ef --version`: `10.0.12`.
- `dotnet restore backend/backend.sln --locked-mode --verbosity:quiet`: superato.
- `dotnet build backend/backend.sln --no-restore -c Release`: superato, zero errori.
- `dotnet test backend/backend.sln --no-restore -c Release`: 146 superati, 0 falliti, 0 ignorati; integrazione su MySQL 8.4 effimero.
- Audit NuGet con `dotnet list backend/backend.sln package --vulnerable --include-transitive`: nessuna vulnerabilità segnalata.
- Docker build con restore locked: `docker build -f webserver/Dockerfile -t moneygestor-backend:plt52 .` superato; restore locked e publish completati.
- Smoke run dell’immagine in Development sulla rete Docker isolata con MySQL 8.4 effimero superato; `/health/ready` ha restituito HTTP 200 dopo bootstrap e migrazioni. Container, rete e file settings temporanei sono stati rimossi.
- Diff degli script di `GenerateCreateLegacySchemaScript` e `GenerateCreateIdentitySchemaScript`, eseguiti su una copia temporanea del commit iniziale e sul nuovo codice con connection string segnaposto non connessa. DDL identico per tabelle/colonne/indici/vincoli; cambia la versione registrata in `__EFMigrationsHistory` da `8.0.20` a `10.0.12`. Nessuna connessione a un database è stata aperta per il confronto.

## Avvisi di compilazione

La compilazione termina senza errori ma conserva warning legacy: `CS0108` per `MoneyMenagerController.Response`, `CS8618` su DTO storici non-nullable e warning `SYSLIB` relativi a API crittografiche preesistenti. Questi warning non sono stati introdotti dal target .NET 10; il workstream QUA-54 gestisce l’obiettivo di warning zero.

## Aggiornare le dipendenze

1. Modificare la versione centrale in `backend/Directory.Packages.props` (o la dichiarazione diretta se il package non è centralizzato).
2. Eseguire `dotnet restore backend/backend.sln` senza modalità locked e rivedere tutti i lock file modificati e l’audit vulnerabilità.
3. Aggiornare il tool locale con `dotnet tool update dotnet-ef --local --version <versione>` quando necessario; revisionare `.config/dotnet-tools.json`.
4. Verificare in sequenza restore locked, build/test, audit e diff SQL degli script per entrambi i context. Aggiornare l’immagine solo dopo la verifica della matrice runtime/provider.
5. Committare insieme versione dichiarata e lock file risultanti. Container e pipeline devono usare `dotnet restore --locked-mode`.
