# CI-53 — Container hardening e release manuale

**Data:** 30 settembre 2026  
**Stato:** parzialmente completato; CI remota rinviata dal proprietario.

## Container backend

- Il Dockerfile usa i manifest multi-platform Microsoft fissati a digest: SDK `10.0.400` (`sha256:4beef5b8919dcaa2dc924233bd069257e883cc7a061e09088a97d152d6a48510`) e ASP.NET runtime `10.0.8` (`sha256:8c0b6857eab7b2aa57884c839bf4678414606bd7d17370f18a842ac5cf414711`). L’SDK è allineato a `global.json`; nello stage runtime non viene copiato SDK o codice build.
- Il processo usa l’utente `app`. Log e chiavi Data Protection hanno directory dedicate; la key ring è esposta al container tramite volume persistente separato.
- Compose applica filesystem read-only, `no-new-privileges`, `cap_drop: ALL`, limite processi, tmpfs limitato, shutdown grace period e rotazione log. Frontend parte dopo il backend healthy. Bind host loopback per default; MySQL resta esterno.
- Lo shutdown e l’healthcheck usano l’entrypoint diretto e il probe applicativo esistente. La configurazione di Production richiede un percorso persistente per `DATA_PROTECTION_KEYS_PATH`.
